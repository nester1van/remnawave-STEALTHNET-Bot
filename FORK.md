# Форк VPN on Go

Форк [STEALTHNET-APP/remnawave-STEALTHNET-Bot](https://github.com/STEALTHNET-APP/remnawave-STEALTHNET-Bot),
база — тег **`v6.3.1-lts`**, ветка `vpnongo/v6.3.1-lts`.

Этот публичный репозиторий — **релизный**: в ветке `release` лежит ровно та сборка,
которая работает в проде, каждый деплой помечен тегом `deploy-YYYY-MM-DD`. Он
существует, чтобы исполнить §13 AGPL: предложить исходники модифицированной версии
тем, кто пользуется сервисом. Разработка идёт в отдельном репозитории.

Апстрим под AGPL-3.0. Лицензия сохраняется, изменения перечислены ниже, как того
требует §5 лицензии. Продавать сервис на этой основе AGPL разрешает; обязательства
возникают при распространении и при сетевом доступе пользователей к
**модифицированной** версии — то есть исходники нашей сборки должны быть доступны
её пользователям.

## Зачем форк

Не для того, чтобы расходиться с апстримом, а чтобы:

1. **Зафиксировать версию.** У проекта три мажорных релиза за семь месяцев и ноль
   тестов в бэкенде. Тянуть `latest` в систему, которая принимает деньги, нельзя.
2. **Убрать то, что нам не нужно и расширяет поверхность атаки.**

Правки минимальны намеренно: чем меньше расхождение, тем дешевле подтягивать
исправления апстрима.

## Изменения

### Безопасность контейнера API (`docker-compose.yml`)

| Что убрано | Почему |
|---|---|
| `- /etc/ssh:/host-etc/ssh` | Через этот монт админка умела править `sshd_config` хоста. Компрометация веб-панели биллинга давала переписать SSH-конфигурацию сервера. Раздел «Server → SSH» перестаёт работать — управление сервером через биллинг нам не нужно |
| `pid: host` | Контейнер биллинга видел пространство процессов хоста целиком. Для метрик достаточно `/proc:/host-proc:ro`, он оставлен |

Проверено: API стартует и отвечает `/api/health` без обоих.

### Сервис `console` переведён в профиль

Работает с `network_mode: host`, слушает SSH на хосте, а пароль к нему апстрим
хранит в `system_settings` **открытым текстом** (ключ `console_password`). По
умолчанию больше не поднимается:

```bash
docker compose --profile console up -d   # кому нужен
```

## Что НЕ трогаем и почему

**Логику приложения.** Все обнаруженные особенности — два механизма триала,
захардкоженные русские тексты ошибок, отсутствие OpenAPI, кнопка кабинета без
токена — обходятся на нашей стороне: слоем изоляции, словарём ошибок,
настройками. Патчить чужую бизнес-логику значит взять её на сопровождение.

**Цепочку миграций.** Она сломана на чистой БД (`20250220_add_proxy_tariff_nodes`
ссылается на несуществующую таблицу), апстрим обходит это greenfield-сбросом.
Чинить — значит переписывать историю схемы и терять совместимость с их
обновлениями.

## Обновление с апстрима

```bash
git fetch origin --tags
git log --oneline vpnongo/v6.3.1-lts..<новый тег>   # читать CHANGELOG глазами
git rebase <новый тег>
```

После каждого обновления — прогон проверок из основного репозитория:

```bash
npm test
```

```bash
BASE_URL=http://127.0.0.1:5001 BUY=yes npm run smoke
```

Первая команда стенда не требует. Вторая проходит платёжный путь целиком до
конфига по ссылке; без `BUY=yes` покупку пропускает.

Тестов у апстрима нет, поэтому проверка критичного пути «регистрация → тариф →
оплата → подписка → конфиг» целиком на нас.
